# 开发说明

## 架构

```text
耳机或其他媒体控制设备
        ↓ macOS 决定路由
MPRemoteCommandCenter：play / pause / toggle
        ↓
AppDelegate：过滤 pause、状态检查、有限队列、请求过期
        ↓
Shortcut：解析配置 → 创建完整按键序列 → 发送
        ↓
当前前台应用
```

- `main.m`：配置初始化、进程锁、命令行检查及应用入口。
- `MediaSession.m`：注册三种命令，发布/释放 Now Playing 会话。回调异步送到主线程，避免跨线程同步等待。
- `AppDelegate.m`：菜单、权限、串行调度、暂停、休眠/用户会话切换和退出。
- `Shortcut.m`：严格配置校验和可单独测试的事件序列构造；发送使用独立事件源状态。
- `Storage.m`：用户配置初始化和限长日志。

没有后台辅助进程、外部播放器启动转发、音量监听、录音状态检测或隐式自动重试。媒体播放状态仅用于发布会话，不代表目标应用状态。

## 调度约束

最多保留 8 条等待请求。超过 3 秒仍未开始发送的请求丢弃，不在很久之后执行旧动作。`play`、`toggle` 使用同一快捷键；`pause` 在状态检查和入队之前记录 `IGNORED source=pause reason=pause-filter` 并返回，不增加请求计数、不发送快捷键。

每次暂停、休眠或用户会话切换递增代数并清空等待队列；已经进入延迟阶段的请求会检查代数，重新启用不能使旧请求复活。休眠/非活动用户会话期间释放媒体会话，恢复时按开关状态重新发布。这不是对所有锁屏场景的接收保证。

一次发送先创建完整事件组，再在后台依次发送，主线程继续处理菜单和命令。暂停和退出不强行中断已开始的事件组，以保证修饰键释放；等待阶段可以取消。系统状态检查与事件提交无法构成原子操作，目标窗口仍可能在发送期间改变。

应用使用用户数据目录下的文件锁避免不同路径的副本同时运行。正常退出或进程结束后锁由系统释放；无需删除遗留的空锁文件。

## 验证

```bash
./scripts/test.sh
./scripts/build.sh
```

测试覆盖配置缺失/错误类型/重复修饰键/未知字段/时间边界、默认组合键的通用和左侧修饰键标志、反向释放、单键与最多修饰键、`pause` 过滤及日志、空闲/忙碌时不入队、`play` / `toggle` 调度与媒体回调到调度器的集成、重新打开不触发、暂停后取消、权限/按键占用、配置热更新、队列限制、过期、休眠、用户会话切换及退出。

调度测试运行真实调度代码，将事件发送、权限查询及日志目的地替换为测试实现。媒体接收测试替换系统命令中心，验证三种命令注册、暂停/退出时释放以及已排队回调不会在重新启用后执行。不会发送真实键盘输入，不需要辅助功能权限，不创建真实媒体会话。

自动测试和构建无法证明设备兼容性、实际按键送达、目标应用响应或长期会话归属。发布说明应区分代码验证和真实使用反馈；不得把模拟测试通过写成硬件成功率。

## 构建与分发

最低部署版本为 macOS 13。脚本构建当前架构的应用，使用稳定 bundle ID `io.github.houhongxu.eartap`。构建阶段不重置用户配置；安装脚本先停止同一身份的应用，再复制新包。

构建输出不入库。提交前更新 `resources/Info.plist` 中的版本与构建号，并维护 `CHANGELOG.md`。当前没有签名发布流水线或预编译发行包；GitHub Actions 只做构建和自动测试。

公开 API 参考：[MediaPlayer](https://developer.apple.com/documentation/mediaplayer)、[Application Services](https://developer.apple.com/documentation/applicationservices)。
