# 故障排查

## 辅助功能权限

通过运行中的 EarTap 菜单检查权限。若开关已打开但仍提示无权限，可在系统设置的辅助功能列表中移除旧条目，重新添加当前固定安装位置的 EarTap。

本地应用采用 ad-hoc 签名，没有 Developer ID 签名或公证。不要通过关闭系统安全功能解决授权问题。建议从源码构建，并保持安装位置固定。

`--check` 会检查配置并打印当前进程的权限状态；从终端执行可能体现终端启动环境的权限归属，所以实际使用以运行中应用菜单为准。

## 媒体命令没有送达

EarTap 使用 `MPRemoteCommandCenter` 接收系统媒体命令，并发布不播放音频的媒体会话。它不是蓝牙数据包监听器，无法看到每次物理按键。

系统当前播放器、浏览器媒体页面、耳机状态、电脑休眠和设备重连都可能影响分发。暂停再启用映射会重新发布会话，但无法保证长期获得接收权。EarTap 不循环播放静音音频，也不周期性抢占播放器。

如果退出 EarTap 后仍有旧映射反应，请检查之前自行运行的后台工具、菜单栏程序和登录项。EarTap 不自动安装或管理其他工具。

## 暂停命令被过滤

实体测试观察到耳机关机产生 `pause`，正常有效点击产生 `play`。为避免关机误触，当前忽略所有 `pause`，保留 `play` / `toggle`。其他设备的正常按键若产生 `pause` 也会被忽略；这不是蓝牙断连检测，也不解决录音中第二次按键未送达的问题。

## 已发送但无反应

确认手动输入同一个快捷键能生效。EarTap 发送给当前窗口，不打开或激活特定应用。重复按媒体键不会自动选择“开始”或“结束”，目标应用如何处理同一快捷键由它自身决定。

菜单显示的“收到”和“已发送”是本次进程的计数。`SENT` 不代表录音开始、停止或文字已保存。

## 日志标记

| 标记 | 含义 |
| --- | --- |
| `READY` / `CHECK` | 程序启动或权限检查 |
| `RECEIVED` | 接收到了通过过滤的媒体命令或菜单测试请求 |
| `IGNORED source=pause reason=pause-filter` | 暂停命令被过滤，不计入“收到”、不入队、不发送快捷键 |
| `SENDING` / `SENT` | 准备发送 / 已提交按键事件 |
| `NEEDS_ACCESSIBILITY` | 当前进程缺少辅助功能权限 |
| `INVALID_CONFIG` | 配置无效，查看同一行的具体原因 |
| `KEYS_HELD` | 检测到修饰键仍被按住，取消这次发送 |
| `QUEUE_FULL` / `EXPIRED` | 排队过多 / 请求超过 3 秒，丢弃且不重试 |
| `PAUSED` / `ENABLED` | 手动关闭 / 开启映射 |
| `CANCELLED` / `LIFECYCLE` | 生命周期改变导致取消，或系统会话通知 |
| `EVENT_ERROR` | 无法创建按键事件 |
| `STOPPING` | 停止接收，等待正在发送的按键释放后退出 |

日志路径为 `~/Library/Application Support/EarTap/status.log`。提交 issue 前请自行检查日志内容，只提供相关片段，不需要音频、转写文本或完整系统日志。
